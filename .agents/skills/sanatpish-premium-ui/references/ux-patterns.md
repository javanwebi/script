# B2B/B2C UX patterns

- Map user jobs: identify a part, read code/spec, compare variants, ask an expert, request a quote, purchase, track order.
- Organize category > subcategory > optional family > SKU, supporting direct SKU membership in subcategories and search across all families.
- Product selection UIs must show actual linked image beside actual SKU and family with an explicit no-family option.
- Mega-menu-only category groups are presentation/taxonomy entities and should be persisted through approved DB paths, not ad hoc frontend JSON.
- Support meaningful filters, sorting, breadcrumbs, search, keyboard access, visible focus, loading, empty, error and retry.
- On category pages do not use fake pricing, availability or identifiers. If no image, show a truthful placeholder.
- On administrative pages combine related flows, avoid duplicate forms, preview record before committing and request confirmation for destructive operations.
